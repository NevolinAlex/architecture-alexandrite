# Проблемы

## Проблемы производительности/масштабирования

* главная страница MES открывается медленно - операторы жалуются;
* в бизнес процессах компании по производству на определенных этапах присутствуют задержки - на каких не известно;
  клиенты жалуются, компания теряет клиентов и заказы;
* в результате открытия API для принятия заказов от других продавцов - количество просроченных заказов увеличилось,
  жалобы растут;
* отсутствуют понимание архитектуры сервисов stateful/stateless - нет понимания готовности к масштабированию нагрузки;

Через месяц после открытия API компания потеряла несколько крупных контрактов.

Есть понимание, что узким местом при выполнении заказов не является производство, производственные
мощности способны справляться с большей нагрузкой.

## Проблемы во внутренних процессах

* ручной деплой на стенды release/prod;
* E2E сценарии выполняются вручную и перед выпуском релиза, что приводит к задержке выпусков, текущие задержки превышают
  1 месяц;

## Проблемы отказоустойчивости:

* СУБД развернуты не в отказоустойчивой конфигурации;
* отсутствует резервное копирование СУБД (разделы или сетевые диски не указаны; требования и процессы не описаны);
* сервисы запускаются не в отказоустойчивой конфигурации;
* Брокер очередей развернут не в отказоустойчивой конфигурации.

## Проблемы наблюдаемости

* отсутствуют компоненты мониторинга - сервисы, СУБД, очереди сообщений могут быть перегружены, об этом никто не знает;
* отсутствуют компоненты трассировки - нет возможности определить узкие места работы системы;
* отсутствуют компоненты централизованного логирования (запись/просмотр) - анализ логов сейчас не должен вызывать
  проблем, однако в случае масштабирования это может стать трудоемким.

В качестве 3 первых работ на внедрение выбираются работы в соответствии с приоритетами: 1, 2, 3.

Итоговый образ архитектуры спустя пол года:

* внедрены механизмы трейсинга запросов, повышена наблюдаемость работы бизнес-процессов в системе;
* внедрена СУБД для кэширования горячих данных;
* повышена устойчивость к сбоям через внедрение механизмов репликации для СУБД, брокера; потеря данных на одном узле не
  ведет к потере в целом;
* обеспечена возможность горизонтального масштабирования сервисов, сервисы работают минимум в 2 экземплярах.
